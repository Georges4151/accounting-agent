# 建筑企业智能会计凭证系统 · 项目说明

## 1. 项目简介

本项目是一套面向中小建筑企业的智能记账系统，后端基于 FastAPI，前端基于 Vue 3，覆盖从凭证录入到期末结账、报表出具的全流程。它主要解决三个问题：手工录凭证慢且容易选错科目、发票信息需要重复誊抄、报表因为数据不规范经常对不上账。系统用"历史分录检索 + 大模型"推荐会计科目，用视觉大模型识别发票并一键生成凭证，同时内置多账套、双人复核、自动折旧、期末结转和三大报表，让一个会计就能规范地管完一家公司的账。

## 3. 功能清单

**账务核心**
- 多账套管理：新建/归档账套、按成员授权，账套间数据完全隔离
- 会计科目表：树形科目、期初余额、辅助核算、停用控制
- 凭证全生命周期：草稿 → 提交 → 出纳复核 → 审核 → 记账，支持反审核、红字冲销、凭证模板
- 凭证自动编号：按"凭证字 + 年月 + 序号"生成，如 记-2026-11-001
- 期末处理：试算平衡检查、损益结转、期间结账、反结账
- 期初建账与数据导入导出（Excel）

**AI 能力**
- 科目智能推荐：根据摘要和金额给出科目编码、名称和置信度
- 常用摘要推荐：选中科目后推荐该科目历史高频摘要，支持输入实时过滤
- 自然语言生成凭证：一句话描述业务，自动生成借贷分录
- 票据识别：发票 / 银行回单 / 费用报销单，识别后一键转凭证
- 财务知识库问答：上传制度、政策文档，ChromaDB 向量检索后回答并给出出处
- 智能助手：RouterAgent 识别意图后分发给记账、报表、税务、分析、问答 5 个专业 Agent，SSE 流式输出

**报表与分析**
- 资产负债表、利润表、现金流量表
- 总账、明细账、日记账、科目余额表、试算平衡表
- 财务比率分析、仪表盘、异常凭证检测

**资产与其他业务**
- 固定资产卡片与自动折旧（支持历史月份补提）
- 预算管理、工资管理、税务计算
- 银行账户、银行对账、应收应付与账龄分析
- 多币种与汇率维护

**系统管理**
- RBAC 权限（管理员 / 会计 / 审核员 / 出纳）、审计日志
- 数据备份与恢复、通知中心、系统参数设置、API Key、USB Key 归档

## 5. 项目亮点（个人贡献）

- **设计了"检索 + 大模型"的科目推荐链路**：输入摘要与金额 → 关键词抽取 → 检索历史分录 → 按使用频次投票，置信度 ≥ 0.85 直接命中；不足时再调用大模型，模型不可用时回退规则库。既保证准确率，又避免每条分录都打一次模型。
- **独立实现凭证状态机与双人复核**：draft → submitted →（现金/银行科目出纳复核）→ reviewed → approved → posted；制单人不能复核自己制单的凭证，出纳复核可通过系统设置开关，权限判断下沉到接口依赖。
- **实现 Excel 式分录录入交互**：Tab / Enter / 方向键导航、Ctrl+V 粘贴多行数据、3 秒防抖自动保存草稿、800ms 防抖触发 AI 推荐、借贷不平衡时红色脉冲提示，录凭证基本不用碰鼠标。
- **实现固定资产自动折旧引擎**：新建资产若购置日期早于当前月，自动从购置月起补提至上月；折旧一直计提至净值等于残值才停止，而不是到了最大使用月数就截断。
- **用 LangGraph 编排多 Agent**：RouterAgent 负责意图识别与分发，记账、报表、税务、分析、问答 5 个子 Agent 各自持有工具，前端通过 SSE 流式接收结果。
- **设计多租户权限模型**：Book + BookMember 关联表控制可见账套，账套相关接口强制使用 URL 路径中的 book_id 做校验，避免只信任请求头导致越权。
- **统一科目类型枚举并做启动迁移**：将历史数据中的中文类型（资产/负债/损益/成本）统一迁移为 asset/liability/revenue/expense/cost，从根上解决了报表取数为空的问题。
- **工程规模**：后端 105 个 Python 模块、约 2.18 万行，231 个 REST 接口，按 api → service → model 分层；前端 85 个文件、约 2.68 万行。

## 7. 运行步骤

**环境要求**：Python 3.11+（开发环境为 3.13）、Node.js 18+、可选安装 Ollama（不装则 AI 功能降级为历史检索 + 规则）。

**① 启动后端**

```powershell
cd backend
pip install -r requirements.txt
```

在 `backend/.env` 中确认关键配置：

```ini
DATABASE_URL=sqlite+aiosqlite:///./accounting.db
KEY_ENCRYPTION_KEY=<32 位 url-safe base64 的 Fernet 密钥>
SECRET_KEY=<JWT 签名密钥>
OLLAMA_BASE_URL=http://localhost:11434
```

```powershell
python main.py
```

首次启动会自动建表、迁移科目类型、初始化科目表并补做当月折旧，导入 ChromaDB、LangChain 等依赖较慢，耐心等 1~2 分钟，看到 Uvicorn 监听 8000 端口即成功。

**② 启动前端**

```powershell
cd frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:5173`，用管理员账号登录后先建账套、维护期初余额，再开始录凭证。

**③ AI 能力（可选）**

```powershell
ollama serve
ollama pull qwen2.5        # 对话与推荐
ollama pull qwen3-vl       # 发票识别
```

**④ Docker 部署**

```powershell
docker compose up -d --build
```

## 9. 常见问题（FAQ）

**报表打开全是 0 / 数据为空**
科目类型中英文混用导致报表按 type 过滤取不到数。系统启动时会执行 `_migrate_account_types` 把"资产/负债/损益/成本"统一转成 asset/liability/revenue/expense/cost。若仍为空，重启后端并强制刷新前端（Ctrl+F5），再看该账套科目表 type 字段是否正确。

**前端带着 token 调接口却返回 401**
FastAPI 默认的 `redirect_slashes=True` 会把 `/api/books` 307 重定向到 `/api/books/`，浏览器重定向时丢掉 Authorization 头。解决方式是创建 app 时设置 `redirect_slashes=False`。

**代码改了，页面没变化**
Vite 偶尔缓存旧模块，Ctrl+F5 强刷；仍不行就重启 `npm run dev`。

**新建的固定资产，以前月份没有折旧**
创建资产时若购置日期早于当前月，后端会自动从购置月补提至上月，补提完成后要重新从数据库刷新对象再返回，否则前端看到的是旧净值。

**USB Key 换台电脑就验证失败**
密钥文件绑定了生成时所在 U 盘的序列号（存的是 SHA-256 摘要），校验时由后端通过 PowerShell 读取当前 U 盘序列号比对，换盘必然失败。前端不接收、也不展示序列号。

**同一张发票能重复录入吗**
不能。发票号在同一账套内唯一，识别和手工修改时都会做重复校验。

**AI 推荐没反应**
先确认 `ollama serve` 已启动、模型已拉取。Ollama 不可用时接口会自动降级为"历史分录 + 规则库"，只是置信度会低一些，不影响录账。

**出纳复核按钮不显示**
只有涉及现金/银行科目（1001/1002/1012）的凭证才需要出纳复核，且系统设置中需开启"出纳复核"开关；制单人也不能复核自己的凭证。

**后端第一次启动很慢**
首次启动要建表、迁移科目类型、初始化科目、加载 ChromaDB 与 LangChain，属于正常现象；之后启动会快很多。
